# anythingitechmv.com

Vite + React 18 + TypeScript + Tailwind. Deployed on Vercel. Backed by Supabase (Postgres + auth).
Routing via `react-router-dom`. UI built on Radix + shadcn-style components in `src/components/ui/`.

This is **not** a Next.js project. Ignore any tool, snippet, or doc that assumes it is.

## Build & deploy

- `npm run dev` — Vite dev server
- `npm run build:prerender` — production build pipeline: sitemap → redirect validation → Vite build → static prerender (`scripts/prerender.cjs`, Puppeteer-based)
- `npm run deploy` — `vercel build --prod && vercel deploy --prebuilt --prod`
- `npm test` — Vitest

The prerender step crawls the SPA and emits static HTML per route so the directory pages are indexable by Google.

## Routing & SEO conventions

- **Canonical host: `anythingitechmv.com` (non-www).** Never emit `www.` URLs in canonical tags, sitemap entries, or internal links.
- `vercel.json` owns all 301 redirects (legacy WordPress URLs → new routes, plus category-slug normalizations). When adding redirects, also delete or update any sitemap entry that points at the *source* URL — sitemap URLs must resolve 200, not 301.
- `public/sitemap.xml` is generated by `scripts/generate-sitemap.cjs`. Edit the generator, not the XML.
- `public/robots.txt` declares `Sitemap:` and `Host:` as `anythingitechmv.com`.
- Directory URL shape: `/marthas-vineyard/:town/:category/:business-slug`. Categories use `-and-` form (e.g. `arts-and-entertainment`). Legacy short forms (`arts-entertainment`) are 301'd in `vercel.json`.
- Avoid the placeholder categories `/other` and `/unknown` in the sitemap — `vercel.json` redirects them away.

## Backend

- `api/` — Vercel serverless functions (`contact.ts`, `directory-submission.ts`, `admin/`, `directory/`).
- Supabase migrations in `supabase/migrations/` and helper scripts in `scripts/registry/` (`tsx`-based).
- `.env.local` holds secrets — never commit, never echo.

## Data pipeline

The business directory is maintained via the `registry:*` scripts in `package.json`. Phases: migrate → remediate → harden → validate → export. Run with `--apply` to actually write; default is dry-run.
